# AI Generation Prompts

This project was built iteratively using the following AI prompts:

1.  **Initial Rotation Composition Logic (Task 1):** "I'm working on Homework 1 Problem 7 with a MuJoCo model of an asymmetric body. I need to write the `compose_sequence` function in `scripts/01_rotation_sandbox.py` that takes a sequence of elemental rotations like `('z', np.pi/2, 'current')` or `('x', np.pi/2, 'fixed')`. How do I multiply the 3x3 rotation matrices so that 'current' rotates about the moving body axes (post-multiplication) and 'fixed' rotates about the stationary space axes (pre-multiplication)?"
2.  **macOS MuJoCo Runtime Fix:** "When I run `python3 scripts/01_rotation_sandbox.py` on macOS, MuJoCo crashes with `RuntimeError: launch_passive requires that the Python script be run under mjpython on macOS`. How do I fix this so the passive viewer opens properly on my Mac?"
3.  **Step-by-Step Animation:** "Right now `01_rotation_sandbox.py` just computes the final matrix and snaps the body to the end pose immediately. Can you update it to smoothly animate each elemental rotation step-by-step over 1 to 1.5 seconds at 60 Hz? That way I can clearly see each step happening in the viewer."
4.  **Interactive Viewer Controls & Recording Setup:** "The animation plays immediately as soon as the MuJoCo window opens, which doesn't give me time to set up the camera angle or start screen recording. Can we add a `key_callback` to the viewer so it stays at the initial orientation on startup, and lets me press `[C]` to play the sequence in Current frame, `[F]` to play in Fixed frame, and `[R]` to reset back to identity? I need to capture a 10-20s video showing both cases."
5.  **Non-Commutativity Demonstration Sequence:** "What is a simple 2-step rotation sequence (like 90 degrees about z followed by 90 degrees about x) that produces a visibly obvious difference in final orientation between current frame and fixed frame? Let's make that the default test sequence in `01_rotation_sandbox.py`."
6.  **Verifying Skew-Symmetric Identities (Task 2):** "In `scripts/02_verify_skew_properties.py`, I need to implement `check_identities(R, rng)` for Problem 8. For a given simulated rotation matrix R, generate random vectors v, w, and omega and test the two identities: `R @ (v x w) == (R @ v) x (R @ w)` and `R @ hat(omega) @ R.T == hat(R @ omega)`. Compute the norm residual for both checks and return the maximum residual."
7.  **Residual Logging & CSV Output:** "Now in `02_verify_skew_properties.py`, at each logged simulation time step, print the max residuals in a neat table and also save the step index, simulation time `t`, and both residuals into a `residuals_log.csv` file so I can include the numbers in my homework report."
8.  **Theoretical Residual Explanation:** "The residuals I got in the simulation are around 1e-16 (near machine precision). Why doesn't verifying this numerically in simulation constitute a formal proof of the identities? And what would it imply if the residual was small (e.g. 1e-5) instead of machine precision?"
9.  **ROS 2 TF Broadcaster Setup (Task 3):** "Moving to Problem 9, in `hw01_tf_demo/tf_broadcaster_node.py`, I need to broadcast TF transforms to RViz2 using the same rotation sequence from Task 1. Set up a ROS 2 node that broadcasts a static `space_frame` and an animated `body_frame` relative to `world` using `TransformBroadcaster`."
10. **Frame Separation in RViz2:** "In RViz2, both `space_frame` and `body_frame` are at the origin `(0, 0, 0)`, so their coordinate axes overlap and it's hard to see what's rotating relative to what. Can you add a z-offset parameter for `body_frame` so it sits slightly above the space frame?"
11. **Smooth RViz2 Animation with Cosine Interpolation:** "The TF broadcaster currently just updates the step at low frequency so the frame jumps abruptly from one pose to the next. Can you make the broadcaster run at 30 Hz with a smooth cosine ease-in-out interpolation between steps, plus a short pause between rotations, so the motion in RViz looks continuous and clean?"
12. **Live Parameter Dynamic Toggle:** "Problem 9 says we need a toggle (ROS parameter or keyboard) to switch between current frame and fixed frame live without having to run two separate recordings. Add a parameter callback so that running `ros2 param set /hw01_tf_broadcaster compose_frame fixed` or `current` immediately updates the composition mode and resets the animation cleanly back to identity to show the new run."
13. **Terminal Keyboard Control Thread:** "To make demonstrating and testing in RViz2 even easier during recording, add a non-blocking keyboard listener thread to the ROS 2 node. When the node is running in the terminal, pressing `[C]` should trigger Current frame, `[F]` should trigger Fixed frame, `[R]` should reset to identity, and `[P]` should pause/resume the animation."
14. **Final Review and Polish:** "Review all three scripts (`01_rotation_sandbox.py`, `02_verify_skew_properties.py`, and `tf_broadcaster_node.py`). Make sure all keybindings match between MuJoCo and ROS 2, verify that the CSV logging runs without error, and check that the instructions printed in the terminal clearly guide the user on how to run and toggle each mode."
